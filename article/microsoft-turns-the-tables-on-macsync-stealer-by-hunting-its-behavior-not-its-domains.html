Microsoft Turns the Tables on MacSync Stealer by Hunting Its Behavior, Not Its Domains

Dyve HackaX Intelligence Unit • 2026-08-20 • Verified Intel

The malware can change its address. Its behavior is harder to hide.

Cybercriminals have a familiar trick when security researchers discover their infrastructure: abandon the compromised domain, register another one, move the malware, and keep operating.

That cat-and-mouse game is exactly what Microsoft encountered while investigating MacSync Stealer, a macOS-focused information-stealing malware that has been operating through rapidly changing infrastructure.

Instead of attempting to chase every new domain, Microsoft Defender Experts took a different approach.

They followed the malware’s behavior.

By correlating endpoint activity with recurring network characteristics, Microsoft identified more than 30 domains associated with MacSync Stealer infrastructure. The investigation followed the activity beyond simple command-and-control communication, linking the infrastructure to payload delivery, data collection, staging and ultimately exfiltration. (Microsoft)

The lesson is important for defenders:

Infrastructure can rotate. Attack behavior often doesn’t.

That distinction is becoming increasingly important as malware operators become faster at replacing domains, servers and other disposable infrastructure.


MacSync Stealer: What makes it dangerous?

MacSync is an infostealer, meaning its primary objective is not necessarily to destroy a computer or encrypt files.

Its goal is to quietly collect valuable information.

Depending on the victim environment, the malware can target sensitive information including:

  • Passwords
  • Browser credentials
  • Browser cookies
  • Session information
  • macOS Keychain material
  • Cryptocurrency wallet information
  • SSH credentials
  • AWS credentials
  • Kubernetes configuration data
  • Browser history
  • Sensitive files stored in common user directories

That makes an infostealer particularly dangerous.

A ransomware attack is usually obvious. Files suddenly become inaccessible and the victim knows something is wrong.

An infostealer can be different.

The victim may continue working normally while credentials, authentication material and other sensitive information are quietly collected and sent to an attacker-controlled server.

Once stolen, those credentials can potentially become the starting point for additional attacks against cloud services, developer environments, cryptocurrency accounts, corporate systems or other connected services.


The attack begins with a social-engineering trick

One of the most interesting parts of the MacSync campaign is not the malware itself.

It is how victims are convinced to run it.

The campaign has been associated with a technique commonly known as ClickFix.

The basic idea is simple and extremely effective.

A victim visits a malicious or compromised webpage and is presented with a fake problem.

The website may claim that:

  • The browser needs an update.
  • A security check has failed.
  • A document cannot be opened.
  • The user needs to verify something.
  • A system component needs to be repaired.

Instead of simply downloading an executable, the victim is instructed to perform a seemingly legitimate action.

That action can involve opening Terminal and pasting a command.

The user thinks they are fixing a problem.

They are actually executing the attacker’s instructions.

This is why ClickFix is particularly dangerous: the victim becomes part of the execution chain.

Microsoft’s previous research has also documented ClickFix campaigns targeting macOS users with fake utility lures designed to deliver information stealers. (Microsoft)


Why blocking domains wasn’t enough

At first glance, domain blocking sounds like an obvious defense.

If a malware campaign uses:

malicious-domain.com

security teams can block the domain.

The problem is that attackers can simply move.

Today it is:

malicious-domain.com

Tomorrow it becomes:

another-domain.com

Then another.

And another.

The malware itself may remain substantially unchanged.

That creates a fundamental weakness in purely infrastructure-based detection:

The defender is chasing addresses while the attacker is changing addresses.

Microsoft’s investigation demonstrated a different strategy.

Rather than asking:

“Which domain is the malware using?”

security researchers asked:

“What does the malware consistently do after it gets onto the machine?”

That shift dramatically expands the detection surface.


Microsoft’s behavioral approach

Microsoft Defender Experts correlated multiple endpoint and network characteristics to identify infrastructure associated with MacSync.

The investigation looked at recurring elements including:

  • Process ancestry
  • Command-line behavior
  • Network request paths
  • HTTP headers
  • Upload parameters
  • Payload retrieval patterns
  • Data staging
  • Exfiltration behavior

The important point is that Microsoft did not treat a domain as malicious simply because it appeared suspicious.

Multiple behavioral indicators had to line up before infrastructure was connected to the malware.

That creates a much stronger analytical model.

A domain can change.

A server can change.

An IP address can change.

But if the malware continues using the same execution sequence, request structures and exfiltration mechanisms, defenders can still identify it.

Microsoft ultimately connected more than 30 domains through this behavioral analysis. (Microsoft)


The fingerprints MacSync leaves behind

MacSync’s infrastructure may rotate, but its operational behavior leaves recognizable fingerprints.

Microsoft observed recurring patterns associated with payload retrieval, command-and-control communication and data exfiltration.

One example involves curl, a legitimate command-line utility available on macOS.

The problem is not curl itself.

Attackers frequently abuse legitimate system utilities because they are already trusted and installed on the machine.

In MacSync activity, defenders can look for suspicious combinations involving shell execution, curl, recurring request paths and other command-line characteristics.

Microsoft’s research identified recurring paths including:

  • /curl/
  • /dynamic?txd=
  • /gate?buildtxd=

These patterns become useful because they can survive infrastructure changes. (Microsoft)


The malware doesn’t just communicate. It collects and ships data.

This distinction is critical.

A suspicious connection to an external server could indicate many things.

It could be telemetry.

It could be software updating.

It could be a legitimate application.

But when network activity is correlated with suspicious endpoint behavior, the picture becomes much clearer.

Microsoft’s investigation found activity extending from payload retrieval to collection, staging and exfiltration.

The malware can collect sensitive information, prepare it for transmission and then upload the stolen material to attacker-controlled infrastructure.

One observed mechanism involves curl making HTTP PUT requests while using upload parameters associated with chunked transfers.

Parameters such as:

  • upload_id
  • chunk_index
  • total_chunks

can provide additional signals for defenders hunting for the activity.

This is significant because it moves detection beyond the question of where data is going.

Security teams can also investigate how the data is being prepared and transmitted.


/tmp/sync

becomes another clue

MacSync’s activity can also leave artifacts on the local machine during the staging process.

Microsoft observed collected information being prepared under temporary paths before exfiltration.

Archives associated with the activity can appear under locations such as:

/tmp/sync

before the data is transmitted.

This creates another behavioral pivot.

A defender doesn’t necessarily need to know the attacker’s current domain to investigate suspicious activity.

A sequence such as:

Terminal activity → suspicious shell execution → payload retrieval → AppleScript activity → temporary archive creation → outbound upload

can be much more informative than any individual indicator by itself.

That is the core of modern behavioral threat hunting.


Why legitimate macOS tools are part of the problem

MacSync’s activity also demonstrates a broader trend in malware development: attackers increasingly abuse legitimate operating-system capabilities.

Instead of bringing an entire collection of unusual tools onto a victim’s machine, malware can combine utilities that are already present.

MacSync activity has involved tools and mechanisms such as:

  • curl
  • zsh
  • osascript
  • Base64 decoding
  • Compression utilities
  • Native macOS functionality

None of these tools are inherently malicious.

That is precisely why they are useful to attackers.

Security teams therefore need to pay attention to context and process relationships, not simply whether a particular executable exists.

For example:

curl running during a normal software update is not inherently suspicious.

But:

Terminal → curl → unusual remote path → decoding → AppleScript execution → credential access → archive creation → outbound PUT

is a very different story.

The sequence matters.


The bigger threat: stolen credentials can become access

The danger posed by MacSync does not necessarily end when the malware finishes running.

Information stealers are valuable because stolen data can be reused.

A compromised browser session may potentially give an attacker access to an authenticated service.

A stolen password can become an entry point.

An exposed SSH key can potentially provide access to development infrastructure.

Cloud credentials can create another path into an organization’s environment.

Cryptocurrency-related information can have direct financial consequences.

This is why infostealers have become such an important part of the modern cybercrime ecosystem.

The malware itself may be relatively small.

The consequences of the information it steals can be enormous.

This is where threat intelligence gets interesting

There is a subtle but important distinction between IOC matching and behavioral threat hunting.

Traditional IOC-based detection might look like this:

“Is the computer communicating with a known malicious domain?”

Behavioral hunting asks:

“Is the computer exhibiting the sequence of actions associated with this malware?”

The second question is much harder to evade.

If an attacker changes:

  • Domain
  • IP address
  • Hosting provider
  • TLS certificate
  • File name
  • Download location

the IOC may become useless.

But if the attacker continues:

  • launching a shell,
  • retrieving content with a recognizable command pattern,
  • decoding the payload,
  • accessing sensitive stores,
  • staging files,
  • and uploading chunks through a recurring request structure,

the behavioral signal remains.

That is the strategic value of Microsoft’s investigation.


What defenders should watch for

Organizations with macOS fleets should not rely solely on domain blocking.

Microsoft recommends combining user education with endpoint and network monitoring.

Security teams should pay particular attention to:

1. Unusual Terminal activity

Investigate Terminal or zsh sessions that appear immediately after a user visits an untrusted webpage or interacts with suspicious content.

2. Suspicious

curl

execution

Look for command-line patterns where curl retrieves unexpected content, particularly when combined with unusual paths, headers or follow-on execution.

3. AppleScript activity

Investigate unusual osascript execution, especially when it rapidly leads to network activity or shell execution.

4. Temporary archive creation

Look for suspicious archive files appearing in temporary directories before outbound network connections.

5. Chunked HTTP uploads

Monitor unusual HTTP PUT activity involving upload identifiers, chunk indexes and total-chunk parameters.

6. Credential-store access

Correlate suspicious shell activity with access to Keychain material, browser credentials, SSH keys and cloud configuration files.

7. New or suspicious domains

Domain reputation still matters.

The lesson is not to abandon domain blocking.

It is to stop treating domain blocking as the entire defense.


The human firewall still matters

There is another lesson buried inside the technical investigation.

A sophisticated malware family can still depend on a remarkably simple action:

someone pastes a command they were told to paste.

That means security awareness remains an important control.

Employees, developers and other users should be trained to treat unexpected instructions asking them to:

  • Open Terminal
  • Paste commands
  • Disable security controls
  • Install “urgent” updates
  • Run scripts
  • Copy commands from websites
  • Execute commands supplied through chat or pop-ups

with extreme caution.

A website should not need to convince a normal user to execute an unexplained shell command simply to prove that they are human.


Apple is also strengthening macOS defenses

The development is particularly relevant as macOS becomes an increasingly attractive target for information stealers.

Apple has introduced additional protections in recent macOS versions, including mechanisms designed to make suspicious Terminal paste-and-execute behavior harder to abuse.

Microsoft’s broader research also shows that endpoint telemetry can be used to reason about malicious behavior rather than relying exclusively on static signatures. (Microsoft)

This reflects a broader industry direction:

security products are increasingly trying to understand what software does, not merely what software is called.


What MacSync teaches the cybersecurity industry

The MacSync investigation is bigger than one malware family.

It demonstrates a fundamental principle of modern threat intelligence:

Attackers can rotate infrastructure faster than defenders can manually block it.

If defenders only react to domains, attackers can keep moving.

If defenders understand the underlying behavior, infrastructure rotation becomes much less effective.

That changes the economics of detection.

Instead of maintaining an endless list of individual domains, security teams can build detections around recurring behaviors and relationships.

This is particularly important in an era where attackers can automate infrastructure deployment and rapidly replace compromised or exposed servers.


Dyve HackaX Analysis: The real takeaway

MacSync Stealer is a useful example of how modern malware campaigns are evolving.

The malware does not need to maintain one permanent command-and-control server.

It does not need to use an obviously malicious executable name.

And it does not necessarily need a sophisticated zero-day vulnerability.

Instead, the operation combines:

social engineering + legitimate system utilities + credential theft + rotating infrastructure + behavioral evasion.

That combination is powerful.

The ClickFix component gets the victim to participate in execution.

The infostealer extracts valuable information.

The rotating infrastructure makes simple blocking less effective.

And the use of legitimate macOS utilities helps the activity blend into normal system behavior.

Microsoft’s response therefore represents a broader change in defensive thinking.

The question is no longer simply:

“Where is the attacker?”

It is increasingly:

“What does the attacker’s software consistently do?”

That is a much harder question for malware operators to evade.

And for defenders, it may be the difference between chasing the next malicious domain and actually understanding the campaign behind it.


Bottom Line

MacSync Stealer is another reminder that cybersecurity cannot depend on static indicators alone.

Microsoft Defender Experts were able to connect more than 30 domains by correlating recurring endpoint and network behaviors across the malware’s attack chain. The investigation showed that even when infrastructure changes, execution patterns, request characteristics, staging behavior and exfiltration techniques can provide durable detection opportunities. (Microsoft)

For organizations defending macOS environments, the practical message is straightforward:

Block known malicious infrastructure — but hunt the behavior behind it.

Because domains can disappear overnight.

Behavior leaves a trail.
